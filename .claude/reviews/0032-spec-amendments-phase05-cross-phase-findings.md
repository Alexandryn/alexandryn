## Summary

Both agents read the three new phase-05 specs together as a batch against `architecture-desktop-host.md` (the phase-01 spec all three implement), ADR 0005, and the phase-05 roadmap — the same cross-spec pattern used for phases 03 and 04 (reviews `0022`, `0031`). This batch surfaced something the prior two didn't: genuine cross-**phase** contradictions, not just citation drift within phase 05 itself. Two findings were independently caught by both passes — the `--config` flag mismatch against `backend-configuration.md` FR-5, and `desktop-host-window-and-serving.md` FR-3 citing a `frontend-design-tokens.md` output artifact that didn't exist. A third, more serious contradiction — `backend-http-transport.md` FR-6's unconditional JSON-only rule leaving no way for the Go server to serve the frontend at all, which `desktop-host-window-and-serving.md` FR-5 depends on — was caught by one pass and confirmed by cross-reading the other's completeness table. Fixing these required amending two already-`APPROVED` specs from earlier phases, not just the three new ones — the first time this project's spec-review process has needed to reach backward across phase boundaries.

## Contradictions and gaps

This is the first review in this project's history to find a genuine **cross-phase** contradiction — two already-`APPROVED` specs from different phases (`backend-http-transport.md`, phase 03; `frontend-design-tokens.md`, phase 04) that, read together, don't compose, discovered only once a third phase's spec tried to depend on both. This is a structurally different failure mode from phases 03 and 04's own recurring patterns (an FR contradicting its own sibling section; an FR citing a sibling document inaccurately) — those were both catchable by reading within one phase's own batch. This one required reading backward across phases, which no single phase's own cross-spec review is naturally positioned to do. Worth naming for future phases: as the spec surface grows, a downstream phase's own drafting pass is functioning as the actual integration test for upstream phases' specs — which is a legitimate way to catch this, but means earlier phases' `APPROVED` status is never fully final until every phase that depends on them has actually been drafted.

## What was not reviewed

Neither agent executed or compiled anything — documents-only review, same discipline as every prior review in this series. Neither agent independently verified the macOS/Windows-specific API claims (`kqueue`, Job Object) beyond checking consistency with ADR 0005 and `architecture-desktop-host.md`, both of which already flag these as unverified in this environment — that status is unchanged by this review. Neither agent deeply evaluated the specific numeric placeholders (250ms poll, 15s timeout, 3-attempt/1s-4s-9s backoff) beyond confirming they're honestly flagged, consistent with constitution §12.

## Resolution

All 3 Blocking, 12 Major, and 3 Minor findings fixed in this pass, across five files:

- **`backend-http-transport.md`** (phase 03, amended) — new FR-8 (static asset serving, SPA fallback, safe `embed.FS`-backed serving), FR-6 scoped explicitly, Failure modes/Security considerations/Test strategy/Acceptance criteria/References all updated.
- **`frontend-design-tokens.md`** (phase 04, amended) — FR-2 now produces `tokens.css` alongside the Tailwind theme config, API and contracts updated.
- **`desktop-host-process-model.md`** — FR-1 (binary path corrected to ADR 0008), FR-2 (`--config` flag), FR-3 (`/healthz` naming note), FR-4 (renamed `Recovering`, port re-capture), FR-5 (grace-period mechanism corrected, macOS quit override added), FR-6 (Windows mechanism honesty), new FR-7 (single-instance lock) — State transitions, Failure modes, Security considerations, Test strategy, Acceptance criteria, Open questions, References all updated to match.
- **`desktop-host-ipc-surface.md`** — FR-2 (Zod abandonment risk, runtime-iteration mechanism named concretely instead of ambiguous "codegen").
- **`desktop-host-window-and-serving.md`** — FR-3 (`tokens.css` citation, build-time existence check designed), new FR-6 (`Recovering` overlay and port-change reload, main-process-only, no IPC needed) — Non-functional requirements, API and contracts, State transitions, Failure modes, Test strategy, Acceptance criteria, Open questions, References all updated.

All three new phase-05 specs remain `DRAFT` pending maintainer review. The two amended phase-03/04 specs carry their own post-approval-amendment status, needing maintainer re-confirmation same as this project's other amendments (`0025`, `0028`). RED phase has not started for any phase.
