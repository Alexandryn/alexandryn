## Summary

Both agents read the three specs together as a batch against `domain-library.md` (phase 02), `architecture-contracts.md` (phase 01), and the freshly-expanded phase 06 roadmap document — the same cross-spec pattern used for phases 03–05. Both independently converged on the same Blocking finding: `backend-library-api.md` FR-1 defined the library endpoint's result set as "owned only," directly contradicting FR-3's own filter vocabulary one paragraph later (`wanted`/`all`), and the cursor/sort design that follows had no defined behavior for a "wanted"-only row with no `LibraryEntry.added_at` to sort by. This is the exact case both this project's domain model and its own roadmap document name as the central hard case for this phase — a self-contradiction in the one spec responsible for it. Two Major findings were also independently confirmed by both passes: a fabricated `<WorkGrid>` component citation (the same citation-drift pattern reviews `0031`/`0032` already found), and both frontend specs mislabeling phase-04's hand-written fixtures as already-contract-generated when they were never anything but hand-written tier-(b) mocks.

## Contradictions and gaps

This batch's Blocking finding is a variant of the pattern review `0032` first named as distinct from phases 03/04's within-document or within-phase contradictions: here it's a single spec (`backend-library-api.md`) contradicting itself across two adjacent FRs, on the exact question — the "wanted" case — that both the domain model and the roadmap document name as this phase's central concern. The two independently-confirmed Major findings (`WorkGrid`, MSW tier mislabeling) are both instances of the now-three-times-seen citation-drift habit (`0031`, `0032`, and now `0033`) — worth treating as a standing risk in this project's spec-writing process specifically when one spec introduces a UI component or a mechanism a sibling spec then references before or without confirming it landed.

## Resolution

All 1 Blocking, 8 Major, and 7 Minor/Nit findings fixed in this pass, across all three specs and the roadmap document:

- **`backend-library-api.md`** — FR-1/FR-3/FR-4 rewritten to resolve the Blocking self-contradiction (result-set scope, per-filter query composition, per-sort cursor encoding, wanted-only sort key); FR-5/FR-7 citation corrections and hard-delete/idempotency semantics specified; FR-6 gains the mirrored per-membership timestamp; FR-9 gains a concrete `pgx.QueryTracer` measurement mechanism; `limit` validation added to Failure modes; malformed-ID case distinguished from `404`; cursor-stability test given three concrete scenarios; 200-character bound corrected and flagged as a placeholder.
- **`frontend-library-screens.md`** — FR-1 now actually introduces `<WorkGrid>`; `localStorage` given its own justification; FR-6 corrected from "tier-(a) retirement" to "tier-(b) removal," citing the `TODO(phase-06)` marker; Acceptance criteria extended to cover the "wanted" case appearing in the default view.
- **`frontend-collections-screens.md`** — FR-2 consumes the now-real `<WorkGrid>`; FR-4 split into three explicit outcome cases with the ambiguous-outcome case's no-auto-retry design named explicitly; FR-5 corrected the same tier-(a)/(b) mislabeling; Failure modes, State transitions, Test strategy, and Acceptance criteria all updated to match the three-case design; the `/collection/:id` route citation softened to what was actually reserved.
- **`roadmap/06-library/README.md`** — Scope line and filter-vocabulary example corrected to match the fixed `backend-library-api.md`; the MSW exit criterion reworded to state the real change (fixture tier, not shipped-build composition, which phase 04 already guaranteed).

All three specs remain `DRAFT` pending maintainer review — this record covers the specs, not implementation, which doesn't exist yet for this phase. Independent review complete; maintainer sign-off is the next and only remaining step before these specs can move to `APPROVED`.
